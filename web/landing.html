how recovery works

catch it. fix it. prove it.

oopsie uses live evidence and current rules to propose a change. an independent gate decides whether that change can reach the running service.

01

catch the wrong result.

one run returned $1,299.00 instead of $12.99; another returned tenant b's invoice to tenant a. both failures hid behind successful http responses.

02

find a safe way forward.

the hosted investigator and coordinator read the failure, approved policy, and earlier releases. old versions failed tenant isolation or the current data schema, so they proposed a forward repair.

03

act only after the gate holds.

the worker scanned and ran the proposed handler against five unchanged checks, switched the gateway to that exact artifact, and passed fresh public probes twice. the receipt records each decision and the deployed hash.
